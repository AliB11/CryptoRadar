# رادارِ بازار — CryptoRadar

ترمینال سیگنال ارزهای دیجیتال: تحلیل تکنیکال ۱۰۰ دارایی برتر، قطب‌نمای لنگر بیت‌کوین، واگرایی RSI، قفل هم‌گرایی هشت‌عاملی، بک‌تست walk-forward، پرتفوی، هشدار قیمت، PWA و پروکسی داده.

Live: [crypto-radar-five.vercel.app](https://crypto-radar-five.vercel.app)

## اجرا

```bash
python3 server.py
```

یا فقط `index.html` را باز کنید (در این حالت ترمینال مستقیم به CoinGecko وصل
می‌شود و اگر شبکه نباشد به شبیه‌سازی سوییچ می‌کند).

## چیدمانِ پرونده‌ها

`index.html` فقط اسکلتِ صفحه است؛ منطق و استایل در ماژول‌های جداگانه‌اند:

| پرونده | نقش |
|---|---|
| `terminal.css` | سیستمِ طراحی (توکن‌ها، تراکم، شبکه) و استایلِ ترمینال |
| `terminal.js` | موتورِ تحلیل، رندر، بک‌تست، پالت فرمان |
| `protection.js` / `-view.js` | قواعدِ خروج از خرید (فقط مشاوره) |
| `momentum.js` / `-view.js` | غربالِ مستقلِ واچ‌لیست |
| `live.js` | نیمهٔ مرورگرِ پایشِ شبانه‌روزی |
| `lib/monitor.js` | تیکِ سمت‌سرور (همان موتورِ حفاظت + اجرای کاغذی) |
| `lib/store.js` | Upstash Redis / فایل / حافظه |
| `lib/push.js` | Web Push (VAPID + aes128gcm)، بدون وابستگی |
| `api/pulse.js` | نبض؛ چرخه را خودش enforcing می‌کند |
| `api/state.js` | همگام‌سازیِ مرورگر ↔ سرور با کنترلِ نسخه |
| `tools/pinger.mjs` | زمان‌سنجِ ۹۰ ثانیه‌ای |
| `tools/vapid.mjs` | تولیدِ کلیدِ VAPID |

سرور هم فایل‌های استاتیک را می‌دهد هم `/api/proxy` را. بدون سرور هم می‌توان `index.html` را باز کرد؛ در آن حالت ترمینال مستقیم به CoinGecko وصل می‌شود و اگر شبکه قطع باشد به شبیه‌سازی محلی سوییچ می‌کند.

روی Vercel تابع `api/proxy.js` همان پروکسی را با کش درون‌حافظه‌ای اجرا می‌کند.

## پروکسی داده

مرورگر دیگر مستقیم به CoinGecko شلیک نمی‌کند:

- فقط مسیرهای مجاز: `coins/markets`، `global`، `search/trending`، `coins/{id}/ohlc` و Fear & Greed
- کش سمت سرور (۷۰ ثانیه برای بازار، ۱۰ دقیقه برای trending/OHLC/FNG)
- اگر آپ‌استریم ۴۲۹ بدهد، پاسخ کهنهٔ کش برمی‌گردد
- اگر پروکسی نباشد، کلاینت خودکار به API عمومی برمی‌گردد

## PWA و اعلان

- نصب روی صفحهٔ خانه (Android/Chrome و راهنمای Safari)
- کار آفلاین با پوستهٔ کش‌شده + حالت شبیه‌سازی
- اعلان سیستم برای هشدار قیمت، حتی با تب در پس‌زمینه (رفرش آرام هر ۳ دقیقه)

## قابلیت‌ها

- قطب‌نمای لنگر بیت‌کوین و پراکندگی ۱۰۰ دارایی
- امتیاز تکنیکال ترکیبی با تعدیل همبستگی نسبت به BTC
- واگرایی قیمت/RSI، قفل هم‌گرایی ۸ تأیید، مونت‌کارلو
- بک‌تست walk-forward با حد ضرر ATR و اهداف پله‌ای
- پرتفوی، دیده‌بان و هشدار قیمت (`localStorage`)
- واچ‌لیست مومنتوم: فیلتر سابقه، حجم، باند ۱۰–۵۰٪ و بوست جعلی، با ورود پولبک
- پالت فرمان (`Ctrl+K`)، میانبرها (`?`)، پیوند `#coin-id`
- نوار «تغییرات این دور» بعد از هر به‌روزرسانی

## پایش شبانه‌روزی (چرخهٔ ۹۰ ثانیه)

ترمینال در مرورگر اجرا می‌شود، و مرورگر همیشه باز نیست. به همین دلیل بخشِ
«هشدار قیمت» و «حفاظت سرمایه» فقط وقتی کار می‌کرد که تب باز می‌ماند. موتورِ
پایش این مشکل را حل می‌کند: یک کارگرِ سمت‌سرور که هر ۹۰ ثانیه، **مستقل از این
صفحه**، طرح‌های حفاظتی و هشدارها را روی دادهٔ مستقلِ CoinGecko ارزیابی می‌کند
و با اعلان فشاری (Web Push) دستگاه را بیدار می‌کند.

```
زمان‌سنجِ بیرونی ──هر ۹۰ ثانیه──▶ GET /api/pulse
                                      │
                                      ├─ قفلِ کوتاه‌عمر (ضدِ اجرای دوتایی)
                                      ├─ دریافت قیمت + last_updated
                                      ├─ ارزیابی با همان موتورِ protection.js
                                      ├─ ثبتِ اجرای کاغذی + دفترچه
                                      └─ Web Push به همهٔ دستگاه‌ها
```

### چرا زمان‌سنجِ بیرونی؟

کرونِ داخلیِ ورسل روی پلنِ Hobby **فقط یک‌بار در روز** اجازه اجرا دارد؛ هر
دقیقه، مخصوصِ پلنِ Pro است
[۱](https://runhooks.app/blog/bypassing-vercel-hobby-plan-cron-limit/).
اما این محدودیت فقط برای زمان‌سنجِ *خودِ ورسل* است، نه برای درخواست‌های ورودی —
هر چیزی که سرِ وقت به `/api/pulse` ریکوست بزند، همان نتیجه را می‌دهد.

سه محرک به‌طور هم‌زمان کار می‌کنند و شمارشِ چرخه دستِ **سرور** است (ضربانِ
ذخیره‌شده در انبارِ وضعیت)، پس هیچ‌کدام باعث تیکِ دوتایی نمی‌شوند:

1. **همان صفحهٔ باز** — هر همگام‌سازی (هر ۴۵ ثانیه و هنگام بازگشت به تب) در
   صورت لزوم یک `/api/pulse` می‌فرستد. تا وقتی ترمینال باز است، پایش بدون هیچ
   نصبِ اضافه‌ای زنده می‌ماند.
2. **زمان‌سنجِ خارجی** (`tools/pinger.mjs` یا cron-job.org) — تنها راهِ کارِ
   شبانه‌روزیِ کامل، وقتی هیچ تبی باز نیست.
3. **کرونِ روزانهٔ `vercel.json`** (۰۳:۰۰) — تورِ ایمنی؛ اگر همهٔ محرک‌های دیگر
   خواب باشند، دستِ‌کم یک چرخه در روز اجرا می‌شود.

### راه‌اندازی در ۵ گام

**۱. انبارِ وضعیت (Upstash Redis — رایگان)**

یک دیتابیس در [Upstash](https://upstash.com) بسازید و این‌ها را در
تنظیماتِ پروژهٔ ورسل (Environment Variables) بگذارید:

```
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
```

**۲. کلیدهای اعلان فشاری**

```bash
node tools/vapid.mjs
```

خروجی را در متغیرهای محیطی بگذارید:

```
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_SUBJECT=mailto:you@example.com
```

> کلید خصوصی یک اعتبارنامه است؛ آن را commit نکنید. عوض‌کردنِ آن بعداً همهٔ
> اشتراک‌های اعلان را باطل می‌کند و دستگاه‌ها باید دوباره فعال کنند.

**۳. توکنِ پایش**

```
RADAR_TOKEN=<یک رشتهٔ تصادفیِ بلند>
CRON_SECRET=<یک رشتهٔ تصادفیِ دیگر>   # اختیاری؛ همان چیزی که کرونِ ورسل به‌عنوان Bearer می‌فرستد
```
`/api/pulse` هر دو را می‌پذیرد (Bearer با `CRON_SECRET` یا هدرِ `x-radar-token` با
`RADAR_TOKEN`). لازم است، چون وگرنه با ست‌بودنِ `CRON_SECRET` هیچ تبِ بازی
نمی‌توانست ضربان را جلو ببرد.

`RADAR_TOKEN` در بخش «پایش زنده» ترمینال هم وارد می‌شود (در
`localStorage` همان دستگاه می‌ماند). بدون آن، `/api/state` پاسخ نمی‌دهد —
وگرنه هر کسی می‌توانست وضعیتِ پایشِ شما را بخواند.

**۴. تنظیماتِ اختیاری**

| متغیر | پیش‌فرض | معنا |
|---|---|---|
| `PULSE_INTERVAL_SEC` | `90` | چرخهٔ هدف؛ بین ۳۰ و ۳۶۰۰ ثانیه محدود می‌شود |
| `PAPER_AUTO_EXEC` | `true` | ثبتِ خودکارِ اجرای کاغذی؛ `false` یعنی فقط هشدار |
| `PAPER_SLIPPAGE_BPS` | `10` | لغزشِ بدبینانه برای خروج‌هایِ بازاری (۰/۱٪) |
| `RADAR_SPACE` | `default` | فضای نام، اگر چند پرتفوی جدا دارید |
| `RADAR_PROXY_ORIGIN` | خالی | اگر ست شود، تیکِ سرور برای قیمت از پروکسیِ همان دامنه می‌خواند (با کش و بازگشتِ ۴۲۹)؛ خالی یعنی مستقیم از CoinGecko |

**۵. زمان‌سنج را روشن کنید**

روی هر دستگاهی که همیشه روشن است (رسبری‌پای، سرورِ خانگی، کوچک‌ترین VPS):

```bash
node tools/pinger.mjs \
  --url https://crypto-radar-five.vercel.app/api/pulse \
  --token "$RADAR_TOKEN" \
  --interval 90
```

یا با systemd / Docker / pm2. ابزار فقط به Node ۱۸+ نیاز دارد و بی‌حالت است:
اگر بمیرد و دوباره بالا بیاید، ضربانِ قلبِ ذخیره‌شده در سرور تصمیم می‌گیرد کار
چه وقت انجام شود — پس هیچ وقت یک عقب‌ماندگی به انفجارِ تیک تبدیل نمی‌شود.

```ini
# /etc/systemd/system/radar-pinger.service
[Service]
WorkingDirectory=/opt/CryptoRadar
ExecStart=/usr/bin/node tools/pinger.mjs --url https://…/api/pulse --token … --interval 90
Restart=always
[Install]
WantedBy=multi-user.target
```

جایگزین‌ها: [cron-job.org](https://cron-job.org) (هر دقیقه)، UptimeRobot
(هر ۵ دقیقه)، یا ارتقا به Vercel Pro و استفاده از کرونِ داخلیِ هر دقیقه.

### اجرای کاغذی یعنی چه؟

هیچ سفارشی به صرافی فرستاده نمی‌شود. وقتی یک شرطِ خروج محقق می‌شود، سرور آن را
در «دفترچهٔ اجرای کاغذی» با قیمتِ مدل‌شده ثبت می‌کند:

- **حد ضررها** (بازاری): کمی **پایین‌تر** از قیمتِ مشاهده‌شده پر می‌شوند
  (`PAPER_SLIPPAGE_BPS`) — چون در واقعیت هم در حالِ سقوط می‌فروشید.
- **اهدافِ سود** (محدود): در **خودِ هدف** پر می‌شوند، حتی اگر قیمت از آن رد شده
  باشد — چون سفارشِ محدود در قیمتِ خودش پر می‌شود.

مدل عمداً بدبینانه است، نه خوش‌بینانه. هر ثبت برچسبِ `paper: true` دارد و در
دفترچه‌ای جداگانه نگه داشته می‌شود.

**یک نکتهٔ مهم:** صفحه و سرور هر دو با همان موتور (`protection.js`) ارزیابی
می‌کنند، و ارزیابیِ دوبارهٔ یک شرطِ لجام‌زده عمداً هشدارِ تازه نمی‌سازد. پس اگر
تب باز باشد و شرط را زودتر ببیند، طرح با حالتِ «هشدارِ باز» (`pending`) ذخیره
می‌شود؛ ولی همین تیکِ سرور آن هشدارِ ایستاده را **به‌نامِ خودش برمی‌دارد** و
اجرای کاغذی را در دفترچه ثبت می‌کند (`adopted: true`). بدون این گام، هر طرحی که
وسط دو تیکِ بسته‌بودنِ تب لمس نمی‌شد، برای همیشه «هشدارِ بی‌اجرا» می‌ماند و
دفترچه خالی می‌شد — همان چیزی که به‌نظر می‌رسید «اجرای کاغذی کار نمی‌کند».

### همگام‌سازی با مرورگر

دو نسخه از وضعیت وجود دارد: مرورگر (برای نمایش) و سرور (برای پایش). نگارشِ
سرور ملاک است، چون تنها چیزی است که شبانه‌روز اجرا می‌شود:

- هر تغییرِ پرتفوی/هشدار در مرورگر، بالا فرستاده می‌شود.
- هر نوشتن، شمارهٔ نسخه‌ای که بر اساس آن بوده را می‌فرستد. اگر سرور جلوتر رفته
  باشد (مثلاً یک اجرای کاغذی در نیمه‌شب ثبت شده)، پاسخ `409` است و مرورگر
  ابتدا وضعیتِ سرور را می‌خواند — تا یک تبِ کهنه، پرکردنِ شبانه را پاک نکند.
- مرورگر هر ۴۵ ثانیه (و هنگامِ بازگشت به تب) همگام می‌کند و در صورت لزوم
  ضربان (`/api/pulse`) هم می‌فرستد؛ پس تا وقتی تب باز است، پایش زنده می‌ماند.
- اگر تیکِ سرور یک طرح را با «اجرای کاغذی» ببندد، کارتِ همان طرح در بخش
  «حفاظت سرمایه» هم صریح می‌گوید که بسته‌شدن خودکار بوده و موجودی پرتفوی دست
  نخورده است.

### بخشِ «پایش زنده»

همهٔ کنترل‌های «لایو بودن» رادار در یک بخشِ مستقل (شمارهٔ ۱۰ در نوارِ بخش‌ها)
جمع شده‌اند و از بخشِ «نمای کلی» بیرون آمده‌اند:

- **کلیدِ روشن/خاموشِ پایش** — هم به‌صورت نشانگرِ بالای صفحه (با یک کلیک، و
  پرسشِ تأیید هنگامِ خاموش‌کردن) و هم به‌صورت کلید در همین بخش.
- **منبع دادهٔ ترمینال** — «خودکار (زنده)» یا «شبیه‌سازی اجباری»؛ دومی هیچ
  درخواستی به CoinGecko نمی‌فرستد (مناسبِ کارِ آفلاین یا نمایشی).
- **وضعیتِ موتور** — آخرین تیک، تیکِ بعدی، تعداد تیک‌ها، طرح‌های روی سرور،
  قیمت‌های تازه، وضعیتِ اجرای کاغذی، دستگاه‌های اعلان و انبارِ وضعیت.
- **آمادگیِ اجرای کاغذی** — یک فهرستِ کوتاه که می‌گوید چه چیز مانعِ اجراست و چه کاری آن را برمی‌دارد. تسمیهِ «مانع» فقط برای آنهایی است که بدونِ آن اجرای کاغذی ممکن نیست — کلیدِ VAPIDِ نصبِشده یا پرتفویِ خالی فقط نوعِ اطلاع را عوض می‌کند.
- **چرا اجرای کاغذی رخ می‌دهد یا نمی‌دهد** — وضعیتِ هر طرح از دیدِ سرور:
  «در حال پایش»، «هشدار باز»، «بدون قیمتِ معتبر»، «آزمایشی»، «بسته‌شده» و
  مانندِ آن، به‌همراهِ فهرستِ مشکلاتِ آخرین تیک (ستونِ `planStates` و
  `problemList` در ضربان).
- **تنظیمات اتصال** — توکنِ `RADAR_TOKEN` و فضای نام. فضای نام باید در هر دو درخواستِ تنظیمات یکسان باشد: پرتفویو و هشدارها در یکِ فضا نگهمانی می‌روند و تیک‌ها در فضای دیگر؛ اگر یکی را به درخل کنید و دیگری را نه، سرور هیچ طرحی نمی‌بیند و دفترچه خالی می‌ماند. فهرستِ «آمادگی» این جهش را فوراً نشان می‌دهد.
- **دفترچهِ اجرای کاغذی** — با ستونِ «مبنا» که می‌گوید ثبت از خودِ تیک آمده یا از هشدارِ ایستادهِ ثبتِشده،
  به‌همراه با آمارِ سود/زیانِ خالص، نرخ برد و لغشدهِ میانگینِ پرداختی که از همین سطرها حاسب می‌شود.

### تستِ محلیِ کل مسیر

```bash
python3 server.py                                   # ترمینال + همان قراردادِ API
node tools/pinger.mjs --local --interval 90         # تیک‌ها را در همین پروسه اجرا می‌کند
node tools/pinger.mjs --url http://localhost:8080/api/pulse --once
```

«--local» تیک را مستقیماً با `lib/monitor.js` اجرا می‌کند و در همان فایلِ
`.radar-state/kv.json` می‌نویسد که `server.py` می‌خواند — بدون نیاز به اکانتِ
Upstash.

### محدودیت‌ها

- پایشِ سمت‌سرور **هشدار می‌دهد و در حالتِ کاغذی ثبت می‌کند**؛ سفارشِ واقعی
  ارسال نمی‌کند. جایگزینِ سفارشِ حفاظتیِ صرافی نیست.
- چرخه ۹۰ ثانیه است. جهشِ قیمت بین دو تیک ممکن است از دست برود و قیمتِ اجرا
  تضمین نشده است.
- اعلان فشاری روی iOS فقط برای PWAهایِ نصب‌شده (Add to Home Screen) کار می‌کند.
- دادهٔ قیمت از CoinGecko است و `last_updated` در اختیارِ ما نیست؛ نرخِ محدودیتِ
  آن سقفِ دفعاتِ مفید را تعیین می‌کند.

## تست

```bash
npm test          # ۹۵ تست: موتورِ حفاظت، تیکِ سرور، هندلرهای API و راه‌اندازیِ صفحه
npm install       # jsdom را نصب می‌کند تا تست‌های مرورگری هم اجرا شوند
```

بدون `npm install` تست‌های jsdom (راه‌اندازیِ صفحه، هدایتِ ضربان از داخل صفحه،

## واچ‌لیست مومنتوم

بخش «واچ‌لیست مومنتوم» از موتور خرید ترمینال جداست. امتیاز خرید RSI بالای ۷۰ را جریمه می‌کند و برای این چارچوب مناسب نیست. غربال چهار شرط سخت دارد: حداقل ۳۰ روز سابقهٔ قابل اثبات، حجم ۲۴ساعته حداقل ۴۰ میلیون دلار، رشد ۲۴ساعته بین ۱۰٪ و ۵۰٪، و نبود نشانهٔ بوست جعلی (گردش مشکوک حجم، توجه بدون عمق، یا اختلاف بیش از ۱۲ واحد بین چاپ ۲۴ساعته و مسیر ساعتی).

ورود پیشنهادی همیشه پولبک است؛ خرید مارکت در سقف پیشنهاد نمی‌شود. پس‌زدن سقف یا اوج حجم، «خطر نقدینگی خروج» و رد فومو است. محیط بیت‌کوین و پروکسی دامیننس (اختلاف رشد بیت‌کوین با کل بازار) سطح ریسک را عوض می‌کند. شاخص ترس و طمع عمداً در حکم استفاده نمی‌شود. جریان کیف‌پول نهنگ در دادهٔ CoinGecko نیست و به‌جای آن فقط پروکسی ساختاری قیمت برچسب می‌خورد.

جهان زنده، ۱۰۰ ارز برتر به‌علاوهٔ پرترافیک‌ترین‌ها بر اساس حجم است؛ دریافت جهان حجم مسیر بوت را مسدود نمی‌کند. در حالت شبیه‌سازی حکم‌ها بازار زنده نیستند.

## حفاظت سرمایه — فقط خروج از خرید

در بخش «پرتفوی»، کنار دارایی روی «ثبت حفاظت» بزنید. زمان واقعی ورود، تعداد تحت حفاظت، بهای ورود و حد ضرر اولیه را وارد کنید. هدف اول/نهایی، سهم خروج اول، فاصلهٔ متحرک، مهلت نگهداری و قیمت ابطال اختیاری‌اند. دارایی‌های قدیمی خودکار وارد این طرح نمی‌شوند.

- شرایط ورود و ریسک یک‌بار ثبت می‌شوند؛ رفرش، تغییر امتیاز خرید و خرید اضافه، آن‌ها را بازنویسی نمی‌کنند. یک fingerprint محلی، تغییر تصادفی قوانین ثبت‌شده را نامعتبر می‌کند و آن طرح را بی‌صدا فعال نمی‌سازد. برای هر دارایی حداکثر یک طرح فعال وجود دارد؛ خرید اضافه خارج از طرح قبلی می‌ماند.
- حد ضرر مستقل از RSI و سیگنال خرید است؛ موتور اصلاً برچسب BUY/RSI/درجهٔ تحلیل را ورودی تصمیم حفاظتی نمی‌کند. خروج حفاظتی بر برداشت بخشی از سود اولویت دارد؛ عبور مستقیم از هر دو هدف فقط یک هشدار خروج کامل می‌دهد. در اینجا «قطعیت» فقط یعنی شرط خروجِ ثبت‌شده با مشاهدهٔ معتبر تحقق یافته است، نه تضمین ادامهٔ نزول یا قیمت اجرای آینده.
- متحرک درصدی از سود ۱R فعال می‌شود: ورود + فاصلهٔ ورود تا حد ضرر اولیه. سقف مبنا فقط از شروع پایش مشاهده می‌شود و حد ضرر هرگز پایین نمی‌رود. انتقال به نقطهٔ ورود، در صورت انتخاب، بعد از **ثبت کامل اجرای خروج اول** انجام می‌شود؛ نه صرفاً صدور هشدار.
- «ابطال قیمتی» آستانه‌ای اختیاری بین حد ضرر و ورود است؛ تحلیل تازهٔ روند یا موتور شورت نیست. مهلت از زمان واقعی ورود محاسبه می‌شود.
- **هشدار فروش، معاملهٔ انجام‌شده نیست.** تعداد فقط پس از «ثبت خروجی که انجام داده‌ام» و ورود قیمت/تعداد واقعی کاهش می‌یابد. ثبت بخشی از مقدار مجاز است. سوابق و تغییر موجودی با هم در همان کلید `radar_pf` ذخیره می‌شوند؛ هیچ سفارش صرافی ارسال نمی‌شود. سود/زیان ثبت‌شده ناخالص است.
- قیمت مستقل از جدول تکنیکال، با `current_price` و `last_updated` برای شناسهٔ دارایی دریافت می‌شود؛ خروج از صد ارز برتر باعث توقف نظارت نمی‌شود. قیمت مفقود، کهنه‌تر از ۵ دقیقه، نامعتبر یا پاسخ `STALE` مبنای هشدار تازه نیست؛ حد حفاظتی و هشدار قبلی حفظ می‌شوند. این دریافت‌کننده منطق قیمت/امتیازدهی و بک‌تست قبلی را تغییر نمی‌دهد.
- طرح آزمایشی فقط دادهٔ شبیه‌سازی می‌پذیرد و اعلان واقعی بازار نمی‌فرستد. طرح واقعی هیچ‌گاه با دادهٔ شبیه‌سازی ارزیابی نمی‌شود.
- پایشِ **مرورگر** تقریباً هر ۹۰ ثانیه و فقط هنگام اجرای آن انجام می‌شود. برای
  پایشِ واقعیِ شبانه‌روز، موتورِ سمت‌سرور را در بخش «پایش زنده» فعال کنید؛ تا وقتی
  همان تب باز است، خودِ صفحه هم ضربان را می‌فرستد. بسته‌شدن/تعلیق مرورگر، قطعی شبکه و حرکات میان دو بررسی ممکن است باعث ازدست‌رفتن عبور قیمت شوند. قیمت اجرا و اجرای حد ضرر تضمین نشده است؛ این قابلیت جایگزین سفارش حفاظتی صرافی یا سرویس شبانه‌روزی نیست.
- وضعیت و تاریخچه با بارگذاری مجدد حفظ می‌شوند؛ پاک‌کردن دادهٔ مرورگر آن‌ها را حذف می‌کند. توقف پایش فروش محسوب نمی‌شود. تب‌های هم‌زمان در مرورگرهای پشتیبان Web Locks، نوشتن پرتفوی را هماهنگ می‌کنند.
